## AN-03：首次资源确认、开放与取消

**文件：** `activity/ActivitySchedulingService.java`、`ActivityCancellationService.java`；`activity/ActivitySchedulingIT.java`、`ActivityCancellationIT.java`。

**接口：** API-19—21。

- [ ] 为资源部分不足、两活动竞争、取消重复及取消与改期竞争编写集成测试。
- [ ] resource-confirm：锁活动→检查APPROVED_UNRESERVED→SchedulingPort.lockAndCheck→可行才设SCHEDULED/effectiveVersionNo并replaceReservations→写事件。同一事务完成；冲突保留原状态且0条部分预约。
- [ ] publish：仅所有者，SCHEDULED且未开始且risk=NORMAL，置OPEN；不要以“已审批”代替资源确认。
- [ ] cancel：锁活动并保存变更前报名/工作人员收件人快照→ChangePort.cancelPending→SchedulingPort.releaseReservations→活动CANCELLED、报名CANCELLED→事件。已经CANCELLED的合法本人重复取消返回当前结果，不再次释放；先保证所有权，再处理幂等终态。
- [ ] 取消可覆盖待处理改期；必须与改期共享活动锁，保证旧请求不能恢复活动。

```text
resource-confirm事务核心顺序：
  snapshot = activityPort.lock(id)
  assert status == APPROVED_UNRESERVED and expectedLockVersion matches
  result = schedulingPort.lockAndCheck(id, input.plan, expectedAttendees)
  if !result.feasible: return 409 RESOURCE_CONFLICT（无预约写入）
  更新status/effectiveVersionNo/lockVersion
  schedulingPort.replaceReservations(id, versionNo, input.plan)
  eventPort.append(...)
```
