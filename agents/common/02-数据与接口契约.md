# 数据与接口契约 v2.0

所有agent以本文为跨模块唯一契约。字段名、枚举、URL不得各自改名。业务规则见[开发基线](01-开发基线.md)，代码归属见[协作规程](04-协作与集成规程.md)。本文中的代码块是接口定义，非已实现代码。

## 1. 通用HTTP约定

- 前缀 `/api/v1`；JSON使用camelCase，UTF-8；ID均UUID，时间均ISO8601带时区。
- 成功：`{"data":返回对象,"requestId":"追踪ID"}`；列表返回data数组，首版最多200项，按createdAt降序再id升序。数量上限200属于首版限制，响应另加 `truncated:boolean`，前端提示被截断。
- 错误：`{"error":{"code":"业务码","message":"中文可读原因","details":{}},"requestId":"追踪ID"}`。
- 创建成功201，其余成功200；不返回空204，统一以 `{"ok":true}` 表示无实体结果。
- 登录外所有接口需要 `Authorization: Bearer <token>`。账号身份来自令牌，不接收body中的actorId作为授权依据。
- 所有持久化POST/PATCH/PUT要求UUID格式的 `Idempotency-Key`，登录/退出除外；只读preview与alternatives不要求。相同用户key唯一，并记录路由和规范化JSON的SHA256，键被不同请求使用→409 IDEMPOTENCY_KEY_REUSED。
- 常用错误：400 VALIDATION_ERROR；401 UNAUTHENTICATED；403 FORBIDDEN；404 NOT_FOUND；409 STALE_VERSION、INVALID_STATE、RESOURCE_CONFLICT、CHANGE_PENDING、CAPACITY_FULL、ALREADY_DECIDED、IDEMPOTENCY_KEY_REUSED；500 INTERNAL_ERROR。数据库错误不把SQL、密码或堆栈返回前端。
- UI收到409时显示原因并重新GET实体，保留未提交表单；网络超时重试必须重用同一key和请求体，不能每次自动生成新key。

## 2. 统一DTO

以下TypeScript写法用于无歧义描述JSON。Java对应public record，UUID→java.util.UUID，Instant→java.time.Instant，数组→List；各public类型独立文件。TypeScript的extends表示字段展开，Java record不得尝试继承另一个record；nullable字段使用对应可空引用类型，所有数量与版本号均整数。

```ts
type UUID = string
type Instant = string
type Role = 'STUDENT'|'ORGANIZER'|'TEACHER'|'RESOURCE_ADMIN'|'SYS_ADMIN'
type ActivityStatus = 'DRAFT'|'PENDING_TEACHER'|'APPROVED_UNRESERVED'|'SCHEDULED'|'OPEN'|'CANCELLED'
type ChangeStatus = 'AWAITING_CONFIRMATIONS'|'PENDING_TEACHER'|'PENDING_RESOURCE'|'APPLIED'|'REJECTED'|'CONFLICTED'|'WITHDRAWN'|'CANCELLED_BY_ACTIVITY'
type Decision = 'APPROVE'|'REJECT'
type Risk = 'NORMAL'|'AT_RISK'
type ResourceKind = 'VENUE'|'EQUIPMENT'
interface Actor { id: UUID; displayName: string; organizationId: UUID; roles: Role[] }
interface EquipmentNeed { resourceId: UUID; quantity: number }
interface Plan {
  startAt: Instant; endAt: Instant; setupMinutes: number; teardownMinutes: number;
  venueId: UUID; equipment: EquipmentNeed[]
}
interface ActivityInput {
  title: string; description: string; expectedAttendees: number;
  registrationCapacity: number; staffUserIds: UUID[]; plan: Plan
}
interface ActivityView {
  id: UUID; organizationId: UUID; ownerId: UUID; status: ActivityStatus;
  versionNo: number; effectiveVersionNo: number|null; lockVersion: number;
  input: ActivityInput; registrationCount: number; resourceRisk: Risk;
  activeChangeId: UUID|null; myRegistrationStatus: 'ACTIVE'|'WITHDRAWN'|'CANCELLED'|null;
  createdAt: Instant
}
interface VersionCommand { expectedLockVersion: number }
interface ReasonCommand extends VersionCommand { reason: string }
interface ActivityEdit extends VersionCommand { input: ActivityInput }
interface ApprovalCommand extends VersionCommand { decision: Decision; comment: string }
interface ResourceCreate {
  kind: ResourceKind; name: string; category: string;
  capacity: number|null; quantity: number; openFrom: string; openTo: string
}
interface ResourceView extends ResourceCreate { id: UUID; createdAt: Instant }
interface FaultInput { startAt: Instant; endAt: Instant; unavailableQuantity: number; reason: string }
interface AffectedActivity { activityId: UUID; title: string; versionNo: number; resourceRisk: Risk }
interface FaultView extends FaultInput { id: UUID; resourceId: UUID; affectedActivities: AffectedActivity[] }
interface CalendarEntry {
  resourceId: UUID; startsAt: Instant; endsAt: Instant; quantity: number;
  activityId: UUID|null; label: string; risk: Risk; segment: 'SETUP'|'EVENT'|'TEARDOWN'|'FAULT'
}
type ConflictCode = 'VENUE_CAPACITY'|'OUTSIDE_HOURS'|'VENUE_OCCUPIED'|'EQUIPMENT_SHORTAGE'|'RESOURCE_FAULT'
interface Conflict {
  code: ConflictCode; resourceId: UUID; resourceName: string; startsAt: Instant;
  endsAt: Instant; required: number|null; available: number|null; message: string
}
interface CheckResult { feasible: boolean; conflicts: Conflict[] }
interface Proposal {
  baseVersionNo: number; targetPlan: Plan
}
interface Alternative {
  plan: Plan; timeShiftMinutes: number; venueChanged: boolean;
  replacedEquipmentLines: number; explanation: string
}
interface AlternativesView {
  items: Alternative[]; evaluatedCount: number; truncated: boolean;
  offsetsMinutes: number[]; maxEvaluations: number
}
interface Impact {
  oldPlan: Plan; newPlan: Plan; releasedResourceIds: UUID[]; acquiredResourceIds: UUID[];
  retainedResourceIds: UUID[]; requiredStaffUserIds: UUID[];
  registeredUserIds: UUID[]; registeredCount: number; notificationUserIds: UUID[];
  approvalReset: true; originalResourceRisk: Risk; changedFields: string[]
}
interface ChangePreview { check: CheckResult; alternatives: AlternativesView; impact: Impact }
interface ChangeCreate extends Proposal { expectedLockVersion: number; reason: string }
interface Confirmation { userId: UUID; decision: Decision|null; comment: string; decidedAt: Instant|null }
interface ChangeDecision { decision: Decision; comment: string }
interface DecisionRecord extends ChangeDecision { actorId: UUID; decidedAt: Instant }
interface ChangeView {
  id: UUID; activityId: UUID; baseVersionNo: number; targetPlan: Plan;
  reason: string; status: ChangeStatus; impact: Impact; confirmations: Confirmation[];
  teacherDecision: DecisionRecord|null; resourceDecision: DecisionRecord|null;
  lastConflicts: Conflict[]; appliedVersionNo: number|null; createdBy: UUID;
  createdAt: Instant; updatedAt: Instant
}
interface RegistrationCommand { action: 'JOIN'|'WITHDRAW'; expectedVersionNo: number }
interface RegistrationView { activityId: UUID; userId: UUID; status: 'ACTIVE'|'WITHDRAWN'|'CANCELLED'; versionNo: number }
interface NotificationView {
  id: UUID; eventId: UUID; activityId: UUID|null; versionNo: number|null;
  title: string; body: string; readAt: Instant|null; createdAt: Instant
}
interface AuditView {
  id: UUID; activityId: UUID; actorId: UUID; eventType: string;
  versionNo: number; summary: string; createdAt: Instant
}
```

附加校验：title长度1—100；description最多2000；reason/comment最多1000，拒绝和取消理由至少1字。venue的capacity为正整数、quantity必须1、category固定VENUE；equipment的capacity为null、quantity正整数、category非空。openFrom/openTo为HH:mm且同日递增。

Conflict数量单位按资源解释：容量为人数，器材为件数，场地占用为1/0；OUTSIDE_HOURS的required/available为null，页面只显示时间原因，不显示虚构数量缺口。

影响列表按ID去重、排序。released/acquired/retained表示旧新资源ID集合的差集/交集；即使resourceId保留，时间或数量改变仍必须在oldPlan/newPlan差异中呈现。报名人员不计入requiredStaffUserIds，notificationUserIds为组织者、工作人员和有效报名人员并集。

学生公开详情需裁剪input.staffUserIds为空数组，不返回报名人ID列表；version、计划及报名数量可见。ActivityView.myRegistrationStatus只表示当前请求用户。被指定为工作人员或有报名历史的本人也可读对应活动详情。scope=mine对组织者返回本人所有活动，对学生返回本人报名过的活动，多角色取并集；scope=review返回角色有权处理的首次审批/资源确认及存在待处理改期的活动，不能漏掉OPEN中的改期。

ChangeView中registeredUserIds和notificationUserIds仅所有者、同组织教师和资源管理员可见，工作人员读取时两个数组均为空，但registeredCount保持真实。公共description只存公开简介，不存私密审批意见。影响快照的originalResourceRisk是创建时值；UI需另读当前ActivityView.resourceRisk显示最新风险，不能把快照当实时状态。

CalendarEntry的FAULT条目表示不可用容量，quantity为故障数量、activityId=null、label为“资源不可用”，不向普通用户公开故障登记者与私有原因。器材可用量由资源库存减这些条目在相同时刻的数量得出。故障单条数量不得大于资源quantity，多条同时故障仍按可用量下限0计算。

资源确认发生冲突的409详情固定为 `{conflicts:Conflict[]}`；改期最终确认变为CONFLICTED时为 `{conflicts:Conflict[],change:ChangeView}`。其余409的details至少含当前versionNo/lockVersion或当前status（适用时），不泄露无权查看的对象。

## 4. 数据库模型及写入归属

实体ID使用UUID，复合主键按下表。所有时间戳含created_at/updated_at均timestamptz；open_from/open_to为不带时区的time；JSON字段为jsonb；数量/版本/尝试次数为integer；enabled为boolean；状态、角色及类别用text与CHECK约束。除明确标注可空的有效版本、决定、read_at、applied_version_no、last_error等字段外均NOT NULL，意见允许空字符串。各实体保留created_at/updated_at，纯关系表至少created_at。表创建由设计师统一写入 `server/src/main/resources/db/migration/V1__schema.sql`，从本文生成并加外键/索引。后续V2及以上按设计师分配编号追加，不改已应用的V1。表归属表示业务写入方，其他模块通过端口访问。

| 表 | 必需字段（省略通用时间） | 约束及写入方 |
|---|---|---|
| organization | id,name | name唯一；配置seed |
| app_user | id,organization_id,username,display_name,password_hash,enabled | username唯一；PM |
| user_role | user_id,role | 复合主键；PM |
| auth_session | id,user_id,token_hash,expires_at | token_hash唯一，只保存哈希；PM |
| command_receipt | actor_id,idempotency_key,route,request_hash,http_status,response_json | actor_id+key主键；http_status/response_json在事务内占位时可空，成功提交前必须填好；PM |
| resource | id,kind,name,category,capacity,quantity,open_from,open_to | 对应ResourceCreate校验；DS |
| resource_fault | id,resource_id,start_at,end_at,unavailable_quantity,reason,created_by | start<end，数量正；DS |
| activity | id,organization_id,owner_id,status,version_no,effective_version_no,lock_version | version_no从1起、lock_version从0起；AN |
| activity_version | activity_id,version_no,input_json,created_by | 复合主键，input_json完整ActivityInput；写入后不修改；AN |
| activity_approval | id,activity_id,version_no,actor_id,decision,comment | 绑定具体版本，保留历次操作；AN |
| activity_registration | activity_id,user_id,status,version_no | 复合主键；AN；version_no为当前有效安排版本 |

| change_request | id,activity_id,base_version_no,target_plan_json,impact_json,reason,status,teacher_decision_json,resource_decision_json,last_conflicts_json,applied_version_no,created_by | target_plan_json不可修改；CM |

外键：全部用户/组织/资源/活动引用有效实体；reservation的(activity_id,version_no)引用activity_version；change_request的base版本也引用activity_version；activity当前/有效版本指针的复合外键需DEFERRABLE INITIALLY DEFERRED，以允许同一事务创建活动及版本。audit的activity_id可空以支持资源故障事件；HTTP活动审计仅返回对应活动记录。

索引：reservation(resource_id,start_at,end_at) WHERE status='ACTIVE'；resource_fault(resource_id,start_at,end_at)；notification(recipient_id,created_at)；activity(owner_id,status)、activity(organization_id,status)；outbox(status,next_attempt_at)。对change_request(activity_id)创建仅覆盖三个待处理状态的唯一索引。

JSON字段不是无约束临时包：写入前必须用统一record验证、读出按同一record映射；类型版本变更必须迁移，不允许各模块另加拼写相近的私有字段。ActivityView.resourceRisk和registrationCount查询时计算，不持久化易过期的副本。

## 5. Java内部端口

公共类型统一放 `server/src/main/java/com/campus/events/contract/`，由项目经理在M0创建。端口实现属于各业务模块。DTO字段与第2节一致；下面定义内部额外类型。

```java
public record ActivitySnapshot(ActivityView activity, List<UUID> activeRegistrationUserIds) {}
public record EventDraft(UUID activityId, int versionNo, UUID actorId, String eventType,
                         String summary, List<UUID> recipientIds, String title, String body) {}
public record CommandResult(int httpStatus, Object body) {}

public interface ActivityPort {
    ActivitySnapshot get(UUID activityId);
    ActivitySnapshot lock(UUID activityId);
    int activatePlan(UUID activityId, int expectedBaseVersionNo, Plan targetPlan, UUID actorId);
    void bumpLockVersion(UUID activityId);
}
public interface SchedulingPort {
    CheckResult check(Plan plan, int expectedAttendees, UUID excludeActivityId);
    AlternativesView alternatives(Plan plan, int expectedAttendees, UUID excludeActivityId);
    CheckResult lockAndCheck(UUID activityId, Plan targetPlan, int expectedAttendees);
    void replaceReservations(UUID activityId, int newVersionNo, Plan targetPlan);
    void releaseReservations(UUID activityId);
    Risk risk(UUID activityId);
}
public interface ChangePort {
    UUID pendingId(UUID activityId);
    boolean hasPending(UUID activityId);
    void cancelPending(UUID activityId, UUID actorId, String reason);
}
public interface EventPort {
    UUID append(EventDraft event);
}
```

规则：ActivityPort.lock、activatePlan、bumpLockVersion，SchedulingPort.lockAndCheck/replace/release，ChangePort.cancelPending、EventPort.append均要求已有事务（MANDATORY），不得自行REQUIRES_NEW。get与check不承诺锁定。端口实现类不能调用上层Controller。

ActivityPort实现为AN的独立ActivityPortAdapter，依赖自己的Repository、SchedulingPort.risk和ChangePort.pendingId等只读能力。ChangePort实现必须是只依赖自身Repository的ChangePortAdapter，不是依赖ActivityPort的ChangeService，从而避免循环。pendingId返回待处理改期ID，无则null，hasPending与其一致；ActivityView.activeChangeId据此构建。DS的SchedulingPort实现仅依赖资源/预约Repository；预览Controller如需ActivityPort，放在独立查询Service，不注入SchedulingPort实现本身。

activatePlan要求调用者持有活动锁、版本一致、SCHEDULED/OPEN；插入新版本，复制旧元数据，仅替换plan，更新当前/有效版本和lockVersion，更新ACTIVE报名的versionNo，返回新版本号。它不写预约、不发通知。bumpLockVersion要求已持有活动锁，仅递增lockVersion，由改期创建/确认/审批/终态变化等调用；成功activatePlan已递增，不重复调用。cancelPending只改改期表，由活动取消调用者统一递增。内部ActivitySnapshot使用未裁剪的数据，myRegistrationStatus置null；仅HTTP输出按当前Actor填充与裁剪。

lockAndCheck读取新旧资源ID并按UUID排序锁resource行，再检查排除本活动旧预约后的容量；没有锁到任何一项资源、资源缺失或参数无效时失败，不能部分继续。replaceReservations只在同一事务的lockAndCheck成功后调用，旧ACTIVE置RELEASED，再插入新ACTIVE；新活动版本必须已存在。releaseReservations也按相同顺序锁全部旧资源。

EventPort.append同时追加audit与outbox，过滤重复recipientIds。用于活动提交/审批/发布/取消、改期创建/确认/审批/生效/冲突、资源故障。outbox payload至少包含recipientIds/title/body；通知消费者只按该快照投递，不重新计算名单。资源故障可对每个受影响活动追加关联事件；没有关联活动时activityId=null、versionNo=0，不向无关用户广播。事件写入不获取活动行锁。

CommandExecutor由PM实现，入口 `CommandResult execute(Actor actor, UUID key, String route, String canonicalJson, Supplier<CommandResult> action)`。用TransactionTemplate开启/加入业务事务：插入占位receipt（ON CONFLICT DO NOTHING）→锁receipt→验证hash→有结果则原样返回→执行业务→存状态与响应→提交。异常回滚receipt与业务。统一锁顺序为receipt→activity→change→按UUID排序的resource；跨活动的请求首版禁止。

CommandResult.body是完整成功或错误信封（含首次requestId），不是裸data；PM提供Responses.success(status,data)与Responses.error(status,code,message,details)统一构造。Controller直接返回httpStatus和body，不再次包装。receipt保存完整body及status，重放保持首次requestId，防止嵌套data或错误被包装为成功。读取响应的普通GET也使用同样的信封结构。

列表额外提供Responses.list(items,truncated)，返回200及data数组、truncated、requestId。SQL过滤权限后读取201项，只返回前200项，以第201项是否存在确定truncated。前端API层必须保留该标志；日历若被截断，提示缩小日期/资源范围，不得把未加载数据当作空闲。

## 6. 原子改期的实现顺序

```text
CommandExecutor.execute(...):
  snapshot = activityPort.lock(activityId)
  锁change_request，验证状态PENDING_RESOURCE、base版本、角色和活动未开始
  check = schedulingPort.lockAndCheck(activityId, targetPlan, expectedAttendees)
  如果不可行：
    change.status = CONFLICTED；保存check.conflicts；activityPort.bumpLockVersion(activityId)
    eventPort.append(改期资源冲突事件)
    返回409 CommandResult（转换成统一错误结构；事务正常提交）
  version = activityPort.activatePlan(activityId, baseVersionNo, targetPlan, actor.id)
  schedulingPort.replaceReservations(activityId, version, targetPlan)
  change.status = APPLIED；保存appliedVersionNo和资源确认决定
  eventPort.append(改期生效事件，收件人为影响快照中的notificationUserIds)
  返回200 ChangeView；事务提交
```

资源冲突是可记录的业务结果；SQL异常或写入故障必须让事务整体回滚。测试故障点放在activatePlan之后、replaceReservations前后，确认版本指针、预约、change、outbox一起回滚。

## 7. 跨模块修改规程

修改本契约时需写出影响的API-ID、DTO、表、端口与调用方，由项目经理组织一致更新。对应方已写好的代码不能靠临时兼容字段悄悄绕开契约。M0先建立可编译类型；未完成的业务端口只允许在test源码中提供替身，生产请求不得返回伪造成功。
