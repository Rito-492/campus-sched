## 3. 统一运行与验证入口

以下命令是各负责人必须实现的执行入口，并非当前仓库已有工具。M0完成后命令应可用。默认在项目根目录PowerShell运行；Unix可用 `./server/mvnw` 替代 `.cmd`。

```powershell
. ./scripts/load-env.ps1
docker compose up -d db
./server/mvnw.cmd -f server/pom.xml test
./server/mvnw.cmd -f server/pom.xml verify
npm --prefix web ci
npm --prefix web run typecheck
npm --prefix web run test:unit -- --run
npm --prefix web run build
npm --prefix qa ci
npm --prefix qa exec playwright install chromium
npm --prefix qa run test:e2e
pwsh -File scripts/check.ps1 -Scope all
```

- 单元测试由Surefire运行 `*Test`；真实数据库及并发由Failsafe运行 `*IT`，`verify`不得配置跳过它们。数据库不可用应明确失败或报告阻塞，不能绿色通过。
- 本地 `TEST_DATABASE_URL` 指向 `campus_test`，另设用户名/密码。每次测试生成独立schema `t_<UUID去掉连字符>`，Flyway迁移后载入独立数据；schema名严格校验。禁止对campus_dev或外部库清表。
- E2E使用独立Compose测试项目和测试数据库，变量 `BASE_URL`；后端与数据库必须真实，只有前端单元测试允许Mock。默认Playwright Chromium，1366×768，必要页面另测1920×1080与390×844。
- `scripts/check.ps1`支持foundation、activity、scheduling、change、ui、qa、all，对应岗位文件中的测试集合；遇到缺失测试文件或0个测试必须失败，不能吞掉退出码。
- 整体成功依据为退出码0、预期测试数非0、无失败及必要人工UI核对。不得以“构建成功”代替业务正确。

## 4. 策略评价记录格式

测试经理实现 `qa/scripts/evaluate-scheduling.ts`，输入 `test-data/scenarios/scheduling.json`，输出 `artifacts/evaluation/results.csv` 和环境说明。字段：scenarioId、strategy、feasible、timeShiftMinutes、venueChanged、replacedEquipmentLines、evaluatedCount、elapsedMs。

DS提供相同候选生成器和约束检查器上的FIRST_FIT与RANKED策略入口，仅供测试/benchmark调用，不新增公共控制策略API。对同一环境每场景预热1次、测量10次，报告中位数及范围。数据至少包括纯时间冲突、换场地、单器材替换、无解、边界相接、数量峰值和故障。两者都成功且成功率相同也应如实报告。
