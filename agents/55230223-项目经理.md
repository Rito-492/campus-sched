## PM-02：账号、会话与权限基础

**文件：** `auth/AuthController.java`、`AuthService.java`、`UserController.java`、`UserRepository.java`、`BearerTokenFilter.java`、`SecurityConfiguration.java`、`foundation/ActorContext.java`；对应 `auth/AuthIT.java`。

**实现接口：** API-01—06、API-38。ActorContext返回当前Actor；其他模块在service层校验角色与数据归属，不能只依赖URL权限。

- [ ] 编写AuthIT：正确/错误密码、缺令牌、过期令牌、退出、停用后旧令牌失效、非SYS_ADMIN建号403；对应D-AT-01/02。
- [ ] 使用BCrypt存密码，SecureRandom生成32字节随机token，DB只存SHA256哈希，8小时过期。登录失败统一错误，不暴露密码或哈希。
- [ ] BearerTokenFilter每次查启用状态及角色；无需JWT/Redis。正确处理401/403统一响应，不把token写日志。
- [ ] 用户创建校验username唯一、密码至少8位、角色在枚举内、组织存在；purpose=staff只返同组织启用账号；组织列表仅SYS_ADMIN。
- [ ] 前端通过同源代理访问，禁止允许任意源携带敏感凭证。记录本课程演示部署的安全边界。
- [ ] 用真实PostgreSQL跑AuthIT并交杨畅登录请求/响应实例、冯玉琪和杨瀚霖ActorContext用法。

## PM-03：共享幂等与事务执行器

**文件：** `foundation/CommandExecutor.java`、`CommandReceiptRepository.java`、`CanonicalJson.java`；`foundation/IdempotencyIT.java`。

**输入输出：** `execute(Actor, UUID key, String route, String canonicalJson, Supplier<CommandResult>)`，完整语义见公共契约；其他成员不能另写一套请求幂等。

- [ ] 先写相同key并发、不同body复用key、成功重放、异常回滚后重试四组测试。
- [ ] 请求体规范化为对象键排序、稳定JSON；数组保留语义顺序，记录method+规范路由与hash。仅在事务内写receipt和业务数据。
- [ ] 使用ON CONFLICT DO NOTHING及行锁处理同key竞争；已有结果时先重放，再考虑业务版本校验。返回完整首次信封并保留原requestId，不能产生第二次业务效果。实现Responses.success/error供所有Controller一致构造CommandResult。
- [ ] 数据库异常回滚业务和receipt；可预期的CONFLICTED结果按CommandResult提交并返回409。不得全局把所有409都回滚或都提交。
- [ ] 确认事件outbox与业务加入相同事务；不能用内存Map代替持久化幂等。

```powershell
./server/mvnw.cmd -f server/pom.xml "-Dit.test=AuthIT,IdempotencyIT" verify
```

完成：D-AT-08通过；重试不会新增预约/事件的保障能被各业务模块调用。
