## QA-02：跨模块数据库与HTTP验收

**文件：** `acceptance/PermissionsIT.java`、`BookingConcurrencyIT.java`、`ChangeRollbackIT.java`、`CancellationRaceIT.java`、`RegistrationCapacityIT.java`、`NotificationConsistencyIT.java`。

- [ ] PermissionsIT覆盖不同组织、非所有者、SYS_ADMIN无业务审批权、个人通知隔离和日历脱敏。
- [ ] BookingConcurrencyIT同步发出两个活动的资源确认；断言恰1成功、1冲突，失败活动无部分预约，资源峰值不超限。
- [ ] ChangeRollbackIT在新版本写入后/预约替换中触发测试异常，比较事务前后数据库快照：有效版本、ACTIVE预约、改期、outbox均一致。
- [ ] CancellationRaceIT并发取消与改期最终确认；断言最终取消、无ACTIVE预约、待处理改期关闭，旧请求不能复活。
- [ ] RegistrationCapacityIT容量1对20账号并发JOIN，最终仅1条ACTIVE；重复提交和退出恢复名额另测。
- [ ] NotificationConsistencyIT模拟第一次消费失败再恢复，等待条件达成后断言每收件人一条通知，读消息不等于确认。
- [ ] 对旧baseVersion、旧lockVersion、相同key不同body以及资源故障例外执行断言。

```powershell
./server/mvnw.cmd -f server/pom.xml "-Dit.test=PermissionsIT,BookingConcurrencyIT,ChangeRollbackIT,CancellationRaceIT,RegistrationCapacityIT,NotificationConsistencyIT" verify
```

测试不能只检查HTTP200，必须核对持久化状态与数量；并发运行使用两个以上独立事务。预期失败的请求不是“测试失败”，是否通过取决于结果是否符合断言。
