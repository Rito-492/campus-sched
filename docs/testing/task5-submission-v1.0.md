### 验收原则

1. 全部20个业务用例纳入设计；每场景至少1正面和2负面，专项同样核查，不以错误码列表代替具体测试。
2. 每条用例明确可复现前置条件、输入值、步骤、可观测预期及清理。负面用例中“正确拒绝”属于预期结果，并不意味着该测试执行失败。
3. 对全部30项D-AT/N-AT和40项API建立设计追踪；设计覆盖不等于自动化实现覆盖，更不等于执行通过率。
4. 新版用例初始全部标“未执行”。已有测试代码仅列实际实现位置及覆盖边界，不能自动承接旧编号的历史结果。
5. 并发要求独立连接/事务及起跑屏障；状态、数量、版本与事务场景须观察真实数据库；故障注入仅限测试上下文。

### 高风险设计裁决

- 只读资源预览遇资格不足预期403 `RESOURCE_INELIGIBLE`，不能当普通资源冲突返回可行性false；备选生成才过滤不合资格候选。
- 改期创建不要求当时资源可行。最终冲突应提交`CONFLICTED`及冲突事件、返回409并保留原安排；数据库异常应整体回滚，两者不得混淆。
- 幂等重放保持首次完整信封和requestId，先于旧版本校验；异常回滚后允许同键同体重试。
- 自审批/自资源复核四条路径都拒绝；所有者若在工作人员名单不向自己确认，仅所有者时直接待复审。停用工作人员的预建待办保留、决定和时间保持NULL，不以删除待办替代拒绝代签。
- 合法APPROVE空意见仍是合法输入，不把现存空事件摘要缺陷造成的400当正确预期。
- 除契约固定的两类资源冲突详情外，不自行要求每个409都含版本字段；以完整错误信封及重新GET后的状态/版本不变验证。未定义多重违规优先级时，拆分单变量用例，不强造唯一码。
- 新旧版本、预约、报名、审计和outbox分别观察；原安排受保护不等于资源可正常使用，实时`AT_RISK`必须保留。

以上是AI独立基线核对和顶层设计裁决，不等同正式团队审核或产品通过记录。
