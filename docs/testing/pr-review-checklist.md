# PR 评审检查清单 v0.1

> 归属：测试经理（55230316）维护；全体成员评审 PR 时共用本口径。补充 `agents/common/04-协作与集成规程.md` §4（合并规则），不重复其内容。
> 用法：评审人按 §1—§5 逐项核对，按 §6 格式输出结论。发现的问题一律给出行号与依据（契约条目/红线条目），不空泛评论。

## 1. 范围与归属

- [ ] 改动文件全部落在提交者的所有权范围内（04-协作规程 §1 模块所有权表）；不夹带他人未完成修改（04 §4）
- [ ] 提交只含本人改动；无临时文件、无 IDE 配置、无构建产物混入
- [ ] 文档放对目录（`docs/configuration/repo-structure.md` §4 路由表）；未自创目录

## 2. 契约一致性（红线：02 契约 §7）

- [ ] DTO 字段名、枚举取值、URL、错误码与 02 契约**逐字一致**——搜 diff 中的 `enum`、路径字符串、`code:` 值，与契约核对
- [ ] 响应包装只有 `{data,requestId}` 与 `{error:{code,message,details},requestId}` 一种；无第二套包装/认证/幂等机制
- [ ] 持久化 POST/PATCH/PUT 均要求 `Idempotency-Key`（登录/退出/只读预览除外）
- [ ] 预约、改期、取消均经统一 SchedulingPort/端口；无越过端口直写预约表
- [ ] 契约如有变更：走 02 §7 修改规程（列 API-ID/DTO/表/端口/调用方，PM 组织一致更新）——**PR 里私改契约直接打回**

## 3. 真实性红线（共同规则）

- [ ] 未执行的测试/检查没有标"通过"；状态列只有 真实结果 / 未执行 / 阻塞 / 失败
- [ ] `artifacts/` 下的证据由真实运行产生（截图/报告非空、非模板填充）；无 `--list` 等探测动作留下的空结果文件
- [ ] 无 Mock/替身冒充联调结果（M1 单模块 Mock 端口允许；M2/M3 不允许 Mock 服务冒充联调）
- [ ] 测试没有通过改生产逻辑、跳过断言、`@Disabled`、`--skip-tests` 等方式让其表面通过
- [ ] 统计数据（覆盖率/成功率/耗时）可溯源到原始输出

## 4. 测试代码质量

- [ ] 断言落库核对（状态/数量/持久化），不只检查 HTTP 200
- [ ] 并发测试用独立连接/事务 + 起跑屏障；非单连接循环
- [ ] 等待用轮询（expect/await），无长固定 sleep 掩盖时序
- [ ] 预期失败的请求是断言对象（断言 409 码与 details 内容）
- [ ] 失败注入只在测试上下文（替换 bean/挂钩）；无公网故障/重置接口
- [ ] 测试间互不依赖脏状态；有清理（或 schema 级隔离）

## 5. 敏感信息与隐私

- [ ] 无硬编码密码/令牌/密钥（凭据一律环境变量，`.env` 不入库）
- [ ] 无真实账号资料、无泄露的个人隐私数据
- [ ] 公开仓库口径：新文件中人名按现状约定（handoff 接收人用真实姓名是 04 §4 模板要求；README 用拼音缩写）；如团队另行决定全面匿名，按该决定执行

## 6. 评审结论格式

输出三档之一，问题给行号+依据，不空泛：

```markdown
## 评审结论：<必须改 | 建议改 | 放行>

### 必须改（阻塞合并）
- [文件:行号] 问题描述 —— 依据（如：02 契约 §2 / 红线第3条 / 04 §4）

### 建议改（不阻塞，可延后）
- ……

### 已核对无问题的维度
- 范围归属 ✓ 契约一致 ✓ 真实性 ✓ 测试质量 ✓ 敏感信息 ✓

### 遗留风险/说明
- （如：IT 未编译验证，阻塞于 PM 基础工程——如实记录）
```

## 7. 在 agent harness 中的运作方式

- agent 可完成**全部检查项**并产出上述评审报告；GitHub 的 Approve/Request Changes 按钮由人在网页点击（或配置 `gh` CLI 后由 agent 代点）。
- **交叉评审原则**：自己参与的 PR 不自审——QA 分支的 PR 由 AN/DS/CM/UI/PM 之一批准；agent 产出的代码由人类成员或另一岗位的 agent 评审，评审痕迹如实署名。
- 评审意见应贴入 PR Conversation 留痕；"必须改"清零后才合并。
- 合并方式沿用 `git merge --no-ff`（保留原子提交供 handoff 证据链溯源）；PR 页面点 Merge 时选 "Create a merge commit"。
