# 岗位任务分配表（task-assignments）

> **用途**：六岗位的阶段任务分解基线，回答"谁在哪个阶段做什么、交付什么、放哪里"。供全体成员与 AI agent 查阅。
> **维护**：项目经理（冀项阳）维护；重大调整需经阶段评审后更新版本号，由配置经理入基线。
> **与飞书看板的分工**：本表是任务分解的**版本化记录**（任务级、评审后更新）；日常执行与进度状态在飞书任务看板跟踪，本表只维护里程碑级完成状态。
>
> 版本：v0.1（2026-09-25，初始分解；日期排定与开发分工待初始/详细项目计划补充）
> **状态**：初稿，待项目经理评审确认后升为 v1.0 并入基线（任务分解决策属项目经理职权）

## 0. 阶段与里程碑

| 阶段 | 名称 | 主要交付物（对应考核项） | 状态 |
|---|---|---|---|
| P0 | 启动 | 选题说明、角色分工、工具选型 | ✅ 完成 |
| P1 | 初始计划与需求 | 初始软件项目计划、软件需求规范 | ⬜ |
| P2 | 原型与详细计划 | 用户界面原型、详细软件项目计划（含技术栈选型） | ⬜ |
| P3 | 设计与专项计划 | 软件测试计划、配置管理计划、设计文档 | ⬜ |
| P4 | 开发 | 系统实现（交付产品的代码部分） | ⬜ |
| P5 | 测试 | 软件测试设计、测试报告 | ⬜ |
| P6 | 交付 | 交付产品（发布）、用户手册 | ⬜ |

> 具体日期由项目经理在《初始软件项目计划》中排定；P4 的编程/测试人员名单及角色权值分配（程序员 N、测试员 M）在《详细软件项目计划》中确定。

## 8. 文档流转与基线流程（各岗位通用）

1. 负责人完成文档，提交至对应目录（见 `AGENTS.md` §4 目录对照），飞书任务流转至项目经理；
2. 项目经理组织评审，记录评审意见与结论；
3. 修订闭环后，配置经理打基线 tag 并登记基线清单；
4. 基线后的修改必须走变更流程（变更申请 → 评审 → 更新基线，见 `AGENTS.md` §7）。
