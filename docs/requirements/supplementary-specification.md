# 校园活动协同与资源调度系统补充规约

版本：v1.1

日期：2026年10月9日

适用范围：所有业务用例；与[需求规约](software-requirements.md)和[业务规则](business-rules.md)共同使用。

## 1 编写目的

本规约规定系统的可用性、安全性、可靠性、性能、数据、接口及运行约束，为课程项目的设计、实现和质量检查提供依据。表中的验证方法用于制定测试和评审活动，实际结果由测试报告记录。

## 2 可用性与用户界面

| 编号 | 要求 | 验证方法 |
| --- | --- | --- |
| NFR-01 | 业务页面使用中文；明确分开业务审批、资源预约、报名状态及风险；错误给原因和下一步，不用原始异常作为提示 | 角色主线和错误输入人工检查 |
| NFR-02 | 每个数据页面有加载、空数据、失败重试和无权限状态；字段校验贴近输入，冲突及409保留未提交内容 | 模拟网络失败及旧版本请求，核对输入和可恢复动作 |
| NFR-03 | 重要状态持续显示于详情和时间线，不能只闪现提示；目标方案在生效前不替换当前安排 | 改期每阶段截图与实际状态核对 |
| NFR-04 | 1366×768及1920×1080桌面无全页横向溢出；日历滚动局限容器；1024以下导航折叠，768以下对比及日历有列表模式；390×844可查看活动和通知并执行人员确认 | 按指定视口检查长名称、弹窗、0／5方案及移动确认 |
| NFR-05 | 状态含文字或图标，不仅凭颜色；键盘可登录和确认；焦点清晰，弹窗有标题和可达关闭按钮，操作目标约40px以上 | 键盘遍历及弹窗检查，核对视觉规范 |
| NFR-06 | 桌面侧栏224px、顶栏64px、内容边距24px；统一字体、8px间距体系和规范颜色，核心日历／对比／影响／时间线清晰 | 页面与公共界面规范核对，不以截图存在代替通过 |

## 3 安全与访问控制

| 编号 | 要求 | 验证方法 |
| --- | --- | --- |
| NFR-07 | 登录会话有效期8小时，退出、过期或停用即时拒绝后续请求；登录令牌32字节安全随机值，数据库仅保存哈希 | 登录、退出、过期及停用的真实接口测试 |
| NFR-08 | 密码使用BCrypt，创建密码至少8位；响应和日志不含口令、哈希、令牌、数据库凭据；内部错误不泄露SQL或堆栈 | 响应递归字段检查及日志审查 |
| NFR-09 | 后端每次检查最新角色、身份、数据归属和授权范围；资格按活动所有者身份和具体资源校验；本人审批及本人资源复核均禁止 | 角色越权、自审、资格绕过和授权变化测试 |
| NFR-10 | 日历、公开详情、工作人员影响视图及个人通知按职责裁剪；ID可猜测不能取得越权记录 | 直接调用受限详情、名单及他人已读接口 |
| NFR-11 | 浏览器通过同源代理访问API，不允许任意来源携带敏感凭据；令牌仅保存在当前标签页sessionStorage，刷新校验、退出清除 | 同源配置及浏览器存储检查 |

## 4 可靠性与一致性

| 编号 | 要求 | 验证方法 |
| --- | --- | --- |
| NFR-12 | 首次联合预约、改期原子切换和取消应全成功或全失败；数据库异常不得部分更新；冲突终态与执行异常回滚分别处理 | 检查异常前后版本、预约、报名、改期、审计和outbox快照 |
| NFR-13 | 同一资源并发预约不超量，报名不超过容量；活动最多一个待改期；取消与改期竞争不能复活 | 两活动同步竞争、20学生争1名额、取消竞争；独立连接及起跑屏障 |
| NFR-14 | 写命令以同用户幂等键、路由和规范请求体识别；重放首次完整响应，包括原requestId；不同内容复用键返回409；异常回滚后允许原命令重试 | 相同键并发、超时重试、旧版本重放、不同内容及异常后重试 |
| NFR-15 | 审计／outbox与业务同事务；通知投递失败不撤销安排；eventId＋recipientId唯一，消费可重试；已读与确认独立 | 消费首次失败、恢复、重复消费和已读后状态对比 |
| NFR-16 | 刷新、重新登录和后端重启后，活动、预约、报名、改期、通知及记录来自持久化数据 | 成功与冲突主线分别刷新和重启核对 |
| NFR-17 | 资源故障不删除预约，风险实时计算；原有效安排保护与实际资源可用性分别说明 | 故障后改期拒绝／冲突／回滚，核对AT_RISK持续提示 |

## 5 性能与容量

| 编号 | 要求 | 验证方法 |
| --- | --- | --- |
| NFR-18 | 候选搜索最多检查300完整组合，最多返回5个可行方案；排序可解释且相同输入和数据得到稳定结果 | 候选边界、去重及排序测试，记录实际evaluatedCount |
| NFR-19 | 普通列表最多200项并提供truncated，日历查询最多7天；审批页聚合相关改期请求并发不超过6 | 列表上限、日历范围和前端请求观察 |
| NFR-20 | 记录20并发请求的响应时间及最终一致性；搜索评测同环境同候选集，预热1次后测10次，报告中位数及范围 | 保存机器、版本、数据规模、计时范围、原始记录和统计结果 |

性能评价应测量登录、列表、日历、备选搜索和资源确认的实际响应时间，记录数据规模、并发负载、环境和计时范围。以20个并发请求检查响应情况及最终一致性，以300组候选预算评价搜索耗时；测试结果应报告中位数和范围。该负载用于课程质量检查，不表示系统最大承载能力。

## 6 数据与接口约束

| 编号 | 要求 | 验证方法 |
| --- | --- | --- |
| NFR-21 | UUID标识，JSON使用camelCase和UTF-8；API时间带时区、数据库timestamptz、页面上海时间；分钟精度、同日及半开区间语义一致 | 时间转换、午夜、开放时段及边界相接测试 |
| NFR-22 | 数据包含必要非空、唯一和外键约束；活动版本不可变、审批绑定版本、报名唯一、预约历史保留；派生人数和风险不保存易过期副本 | 迁移、约束和版本／关系检查 |
| NFR-23 | `/api/v1`统一响应信封和requestId；业务预览只读；持久化写操作有幂等键，登录／退出例外；健康检查免登录且不泄露配置 | 契约与实际响应核对，预览前后业务表对比 |
| NFR-24 | 资格、身份和授权范围作为明确数据维护，修改可追踪；字段变更应统一DTO及迁移，不在私有JSON中临时塞另一套定义 | 逐字段核对身份、角色、资格和范围在接口、数据库、页面及测试中的一致性 |

## 7 技术、部署与维护

| NFR-27 | 演示使用Docker Compose的db、server、web及Nginx代理；默认本机入口8088；配置与秘密外置，测试与开发库及数据卷隔离 | 按发布说明干净启动，核对环境变量及独立测试环境 |
| NFR-28 | 数据库升级追加Flyway迁移，不改已应用迁移；说明备份与恢复步骤，恢复后核对核心关系；不删除数据卷掩盖迁移失败 | 迁移和备份恢复演练，保存过程证据 |
| NFR-29 | 验证使用真实PostgreSQL；并发和事务测试不以H2／Mock替代；E2E真实接入，fixture仅原型及组件开发并有标识；缺测试或零测试不能判通过 | 单元／集成／E2E日志、证据及数据来源检查 |
| NFR-30 | 需求、设计、接口、页面、测试、手册及发布版本可追踪；未执行、失败、阻塞如实区分；既有基线变更记录原因、范围和复测 | 追踪矩阵、交接单、配置清单和发布记录核对 |

## 8 特殊需求与验收资料

不接外部校园身份、短信或支付；无自动人员排班，无硬件控制，无全局最优承诺。演示数据可以虚构但应标注，不能填入真实秘密或把测试账号当成项目组人员资料。

验收资料应包括软件版本、环境、输入数据、执行步骤、实际结果、失败日志及必要截图。图像注明浏览器、视口和数据版本，界面设计示意与软件运行截图分别标注。

## 9 质量要求的维护

质量要求应与软件需求、界面设计、测试计划和发布环境保持一致。调整性能评价条件、数据管理或运行限制时，应记录修改原因和影响，复核相关测试及文档。质量结论以实际执行记录为依据。
