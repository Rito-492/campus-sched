# 软件需求规格说明

版本：v1.0（依据开发任务包 v2.0；2026-09-26）

## 1. 目的与依据

本文定义校园活动多资源协同调度系统首版的需求。业务规则来自仓库 `agents/common/01-开发基线.md`，接口来自 `agents/common/02-数据与接口契约.md`，验收以 `agents/common/03-验收与演示数据.md` 的 D-AT 场景为准。文中制度均为**演示产品规则**，不表示学校现行制度；目前没有访谈证据，不据此推断校内实际政策。

## 2. 产品范围

首版支持活动创建、编辑、提交审批、教师审批、资源联合确认、开放报名、限额报名与退出、活动取消及预约释放；并支持改期预览、替代方案、工作人员确认、重新审批、资源确认、通知与审计。活动时间、场地、器材在首次确认后只能通过改期改变。

本期不做候补、签到、器材归还验收、通用任务看板、统计报表、自动排班、短信/支付/校园身份集成、硬件接入或全局最优调度。预览方案只说明检查结果，不占用资源。演示和测试数据必须标为虚构，实际运行证据不得预填。

## 3. 用户角色与权限需求

| 角色 | 需求与范围 |
|---|---|
| STUDENT | 查看公开 OPEN 活动及本人参与的历史活动；报名、退出；查看本人通知；仅在被指定为工作人员时确认改期。只能从活动详情读取自己的报名状态。 |
| ORGANIZER | 创建活动；仅编辑、提交、开放、取消自己拥有的活动；查看本人活动名单；为尚未开始的已排期活动发起改期。 |
| TEACHER | 审批本组织活动及改期；不得审批自己作为组织者的活动。 |
| RESOURCE_ADMIN | 管理本校园资源与故障；确认联合预约和改期资源；仅为上述职责读取活动及受影响名单。 |
| SYS_ADMIN | 创建账号、授予角色、停用账号；不因系统管理员身份自动取得教师或资源审批权限。 |

后端必须按令牌身份、角色和对象归属授权，不能信任请求体中的 actorId。未登录返回 401；已登录但越权返回 403；对象确实不存在返回 404。公开详情、日历和资源视图不得泄露工作人员、报名名单、组织者等无权信息；无权查看的占用只显示资源及时间。

## 4. 功能需求

| 编号 | 需求 |
|---|---|
| FR-ACT-01 | ORGANIZER 可创建活动；服务端创建 DRAFT 状态和不可变版本 1。输入须满足活动人数、报名容量、工作人员组织归属、时间、场地及器材约束。 |
| FR-ACT-02 | 所有者仅可编辑 DRAFT。每次编辑生成新版本，既有版本不可改写；版本号表示内容版本，lockVersion 用于并发写入检查，二者不得混用。 |
| FR-ACT-03 | 所有者可提交当前草稿版本供教师审批。提交后冻结该版本；提交本身不得创建预约。 |
| FR-ACT-04 | 本组织且非活动所有者的 TEACHER 可对指定版本批准或驳回并留下意见。批准进入 APPROVED_UNRESERVED；驳回回到 DRAFT。审批记录绑定 versionNo。 |
| FR-ACT-05 | 所有者可从待审批或已批准未预约状态撤回。撤回复制当前内容为新版本并回到 DRAFT；旧审批不适用于新版本。 |
| FR-ACT-06 | RESOURCE_ADMIN 可对已批准未预约活动执行首次资源确认。系统必须在同一事务内锁活动、核对版本、检查整组资源并创建完整预约；冲突时返回 409，状态不变且不得留下部分预约。 |
| FR-ACT-07 | 所有者仅可开放已 SCHEDULED、尚未开始且资源风险为 NORMAL 的活动；开放后状态为 OPEN。 |
| FR-ACT-08 | 所有者可取消尚未开始的非终态活动。取消需保存收件人快照、取消待处理改期、释放活动全部 ACTIVE 预约、取消有效报名并记录事件；合法本人重复取消幂等，不重复释放。 |
| FR-REG-01 | STUDENT 可加入 OPEN 且未开始、没有待处理改期的活动；ACTIVE 报名人数不得超过 registrationCapacity。按活动和用户唯一保存当前报名记录，重复 JOIN 返回既有 ACTIVE 记录。 |
| FR-REG-02 | STUDENT 可退出自己的 ACTIVE 报名；重复退出返回 WITHDRAWN 记录。无历史记录时退出返回 409 INVALID_STATE；重新报名须重新检查容量。 |
| FR-REG-03 | 报名或退出实际改变时递增活动 lockVersion。待处理改期期间 JOIN/WITHDRAW 返回 409 CHANGE_PENDING。 |
| FR-REG-04 | 报名名单仅活动所有者、同组织教师或资源管理员按职责可读；学生仅能读取自己的报名状态。 |
| FR-CHG-01 | 活动所有者可为尚未开始的 SCHEDULED/OPEN 活动预览未来目标安排。预览只返回检查、冲突、有限范围候选方案和影响，不写入预约。 |
| FR-CHG-02 | 每活动最多一个待处理改期。创建时锁活动并校验 baseVersionNo、expectedLockVersion；目标计划与影响快照固定保存。改期所需工作人员（不含组织者）均须确认；无此类人员时直接进入教师审批。 |
| FR-CHG-03 | 工作人员、教师及资源管理员仅能按状态机执行自己负责的决定。任一工作人员拒绝即 REJECTED；全员同意进入 PENDING_TEACHER；教师批准进入 PENDING_RESOURCE，驳回进入 REJECTED。 |
| FR-CHG-04 | 资源管理员最终确认时重新检查目标计划。可行时在一个事务内创建活动新版本、切换预约、将改期置为 APPLIED 并记录事件；不可行时返回 409、记为 CONFLICTED，原有效活动版本和预约保留。 |
| FR-CHG-05 | 活动取消可覆盖待处理改期。改期确认与取消共享活动锁；待处理改期期间报名冻结，终态解除冻结。 |
| FR-READ-01 | 公开列表仅返回 OPEN 活动；mine 仅返回当前用户所有活动；review 按教师组织或资源管理员职责过滤。列表最多返回 200 项并明确标注 truncated。 |
| FR-READ-02 | 活动视图按读取时刻计算报名数、资源风险、待处理改期ID及当前用户报名状态。内部 ActivitySnapshot 不得因 HTTP 视图裁剪而遗漏工作人员或报名用户。 |
| FR-AUD-01 | 提交、审批、开放、取消、报名相关活动变更及改期相关业务操作应在业务事务中追加审计/事件；不得伪造成功响应或吞掉数据库异常。 |

## 5. 数据、时间与质量需求

- 标识符为 UUID；API 时间为带时区 ISO 8601，服务端使用 Instant，数据库使用 timestamptz，页面以 Asia/Shanghai 展示。
- 活动时长 30 分钟至 6 小时，精确到分钟；布场和撤场各 0 至 120 分钟。占用区间为 `[startAt-setupMinutes, endAt+teardownMinutes)`，必须处于同一上海自然日和资源开放时段（初始为 08:00—22:00）。
- `expectedAttendees >= registrationCapacity >= 1`；场地容量不得小于 expectedAttendees。工作人员是启用的本组织账号且去重；组织者可列为工作人员，但不需要确认自己的改期。
- 首版活动仅使用一个主场地和连续时段。器材需求数量为正整数，同一计划中一个资源只能出现一次。场地、器材库存和开放时间创建后不提供修改入口；不可用状态用故障记录表达。
- 所有持久化命令使用统一 CommandExecutor、Idempotency-Key、响应信封和端口契约。预约、释放、改期、取消不得绕开 SchedulingPort 直接写预约表。
- 并发报名、资源竞争、取消与改期竞争、事务回滚需使用真实 PostgreSQL 集成验证；验证结果仅在实际运行后记录。性能先测量并报告，不预设未验证的毫秒目标。

## 6. 外部接口范围

活动与报名模块负责 API-12—23：创建、编辑、提交、我的活动、公开活动、详情、审批队列、教师决定、撤回、资源确认、开放、取消、报名/退出和报名名单。请求/响应字段、HTTP 状态、幂等和错误码以数据与接口契约 §2—3 为准；本文件不复制或另定义 DTO。

## 7. 验收映射

活动与报名需求主要映射 D-AT-02、03、07、15、16、17、20、21；改期交互和活动版本另受 D-AT-09—14、18 约束。逐项测试与实现状态见 [需求追踪](traceability.md)。当前仓库分支没有后端源码或测试工程，因此本文不把任何功能标为已实现或已通过。
