# 校园活动协同与资源调度系统业务规则

版本：v1.1

日期：2026年10月9日

配套文件：[需求规约](software-requirements.md)、[用例规约](use-cases.md)、[补充规约](supplementary-specification.md)。

本文规定角色权限、资源申请资格、时间与数量约束、活动版本、改期、取消和通知的处理规则，为用例描述、系统设计和测试提供共同依据。

## 1 角色与资格

| 编号 | 规则 |
| --- | --- |
| BR-01 | 操作许可由启用账号、角色、业务关系、授权范围和状态共同决定。教师／学生身份独立于申请人／批准人／管理员角色，教师不能因身份自动批准申请 |
| BR-02 | 只有活动所有者能编辑、提交、撤回、发布、改期或取消该活动；批准和资源复核均应回避本人活动。账号管理权限不自动授予业务审批或资源确认权限 |
| BR-03 | 每个场地或设备分别设置教师及学生申请许可；全部所需资源均符合活动所有者身份才允许提交、备选选用、改期申请及最终确认。请求操作者不能替代所有者身份作为资格依据 |
| BR-04 | 资格调整对新申请、未预约申请及新的改期目标按最新设置生效；既有生效预约保留，不因资格调整自动删除。资格修改应记录前后值、操作者和时间 |
| BR-05 | 私有活动日历条目脱敏为“已占用”。公开详情隐藏工作人员ID；工作人员改期视图隐藏全部报名者与通知收件人ID但保留真实人数。名单、审计和审批意见按当前职责及范围授权；通知仅本人读取 |

## 2 时间、人数与资源

| 编号 | 规则 |
| --- | --- |
| BR-06 | 时间使用带时区ISO8601；页面统一Asia/Shanghai。活动时长30分钟～6小时，精确到分钟，布场／撤场各0～120分钟。占用为[startAt−setupMinutes, endAt＋teardownMinutes)，整段处于同一上海自然日及所有所需资源开放时段；默认开放08:00～22:00 |
| BR-07 | 一个活动只有一个主场地和一个连续时段。预计人数≥报名容量≥1，场地容量≥预计人数。工作人员来自本组织启用账号且去重，所有者可列入但不需要向自己确认 |
| BR-08 | 场地同一时刻最多一个有效活动预约，场地quantity固定1。设备按资源池库存管理，数量为正整数，同一计划设备资源ID不得重复；替换仅同category且所需数量不变 |
| BR-09 | 设备任一时刻有效预约总量＋新需求≤max(0,库存−同时故障总量)。应按开始和结束边界统计峰值，相同时间先结束再开始；端点相接不冲突，不把错峰预约简单相加 |
| BR-10 | 故障startAt＜endAt，数量为正且单条不超过库存，场地故障数量只能1；重叠故障使可用量最低为0。故障不删除原预约，受影响活动显示AT_RISK。基本资料创建后不开放修改，资格调整为独立管理操作 |

## 3 活动、版本及报名

| 编号 | 规则 |
| --- | --- |
| BR-11 | 创建为DRAFT版本1，并发版本从0起。只允许编辑草稿，编辑生成不可变新内容版本；提交绑定当前版本且不预约资源。业务批准为APPROVED_UNRESERVED，仍不占用资源 |
| BR-12 | 待审批或已审批未预约可以撤回，复制内容形成新草稿版本并使旧审批失效。驳回回草稿并保留意见；后续编辑再生成新版本 |
| BR-13 | 资源确认重查资格与全部资源；成功才同时写完整预约、SCHEDULED和有效版本。任一失败不产生部分占用；资源冲突保持APPROVED_UNRESERVED |
| BR-14 | 发布仅限本人SCHEDULED活动、尚未开始且当前资源风险NORMAL；发布进入OPEN。业务批准与资源预约分别表达 |
| BR-15 | 学生身份账号仅在OPEN、未开始、有效版本匹配且无待处理改期时可报名／退出。名额仅统计ACTIVE；已有ACTIVE重复JOIN返回原记录，已有WITHDRAWN重复退出返回原记录，无历史退出为INVALID_STATE；重新报名重新校验 |
| BR-16 | 报名关系(activityId,userId)唯一。实际报名变化更新lockVersion；成功改期保留ACTIVE报名并更新关联有效版本，取消活动将有效报名置CANCELLED |

## 4 冲突、备选与改期

| 编号 | 规则 |
| --- | --- |
| BR-17 | 冲突类型沿用VENUE_CAPACITY、OUTSIDE_HOURS、VENUE_OCCUPIED、EQUIPMENT_SHORTAGE、RESOURCE_FAULT。提供资源、精确区间、需求和可用数量及中文原因；开放时间错误数量为null；无权限时不泄露竞争活动身份 |
| BR-18 | 备选偏移按0、−30、＋30、−60、＋60、−90、＋90、−120、＋120分钟生成；保持时长及布撤场，候选场地按UUID升序。设备组合为原组合或只替换一项同类设备；替换不得造成重复ID。过滤过去时间、资格受限及硬约束失败组合 |
| BR-19 | 按偏移→场地→设备组合生成，原组合优先，替换组合按原resourceId及新resourceId升序；最多检查300个完整组合。去重后按(abs时间偏移,是否换场地,替换项数,startAt,venueId,排序后的设备JSON)升序取最多5项，说明evaluatedCount、truncated和范围；无结果不意味着全局无解 |
| BR-20 | 预览、候选选择和影响计算不写预约。选择候选后重新预览实际目标，创建的targetPlan须为最后确认的目标。创建不要求资源当时可行，须校验资格、版本、状态和时间；最终资源复核才决定是否生效 |
| BR-21 | 改期仅限本人未开始的SCHEDULED／OPEN活动，目标开始在未来。每活动最多一个待处理改期；targetPlan及影响快照创建后不可改，更换需撤回后新建 |
| BR-22 | 影响包括旧新计划、释放／获取／保留资源集合、审批重置、除所有者外的工作人员、有效报名和通知人员。集合去重排序；同资源但时间或数量变化仍须在差异中显示。通知人数以去重并集计算，报名人数不能以脱敏后ID数组长度代替 |
| BR-23 | 其他工作人员逐人确认，任一拒绝→REJECTED，全同意→PENDING_TEACHER，无确认者直接待复审。同一人重复相同决定不重复推进，已决定后反向决定为ALREADY_DECIDED；终态不得接受新决定 |
| BR-24 | 复审同意→PENDING_RESOURCE，拒绝→REJECTED；意见仅对该changeId与不可变目标有效。资源管理员拒绝→REJECTED；资源冲突→CONFLICTED，新版本与旧预约不变；须重新申请且审批不可移用 |
| BR-25 | 资源最终确认成功应一次事务新建活动版本、释放旧预约、建立新预约、更新有效报名版本、标APPLIED并写审计与通知事件；活动仍保持原SCHEDULED／OPEN状态。重查排除该活动自身旧预约，但检查其他活动及故障 |
| BR-26 | AWAITING_CONFIRMATIONS、PENDING_TEACHER、PENDING_RESOURCE期间冻结报名和退出，返回CHANGE_PENDING。终态解除冻结但仍检查活动开放、时间和容量；所有者可以撤回待处理改期 |
| BR-27 | 改期失败不得因本次操作改变原有效安排；数据库异常整体回滚并保留原待处理状态。原资源已故障时同时显示AT_RISK，不能承诺原安排可正常使用 |

## 5 取消、幂等与通知

| 编号 | 规则 |
| --- | --- |
| BR-28 | 未开始活动所有者可取消；统一保存收件人快照、关闭待处理改期为CANCELLED_BY_ACTIVITY、释放全部ACTIVE预约、活动CANCELLED、有效报名CANCELLED并写事件。取消与改期共享活动锁，最终不得复活 |
| BR-29 | 先保证所有权后处理重复取消；合法所有者再次取消已取消活动返回当前结果，不重复释放或通知。同用户同幂等键同路由同请求体重放首次完整响应；不同内容复用键返回IDEMPOTENCY_KEY_REUSED。重放应先于旧并发版本校验 |
| BR-30 | 所有业务写入统一事务处理，活动→改期→按UUID排序的新旧资源锁定，重查后写入。故障只锁资源，不反向锁活动；全部预约写入及释放经统一调度端口 |
| BR-31 | 审计和outbox随业务事务提交；业务回滚时一起回滚。通知消费者异步重试且eventId＋recipientId唯一，投递失败不撤销已提交安排；已读只改readAt，不能当作人员确认 |
| BR-32 | 通知处理每2秒一批最多20条，按既有任务约定最多5次重试、延迟2／4／8／16／32秒，最终FAILED保留原因；授权维护人员可使用维护工具重新处理，业务页面不提供无鉴权运维入口 |

## 6 边界示例

1. 场地预约[10:00,11:00)与[11:00,12:00)可以连续使用；后者若布场15分钟，则产生[10:45,11:00)冲突。
2. 库存2，已有[10:00,11:00)×1与[11:00,12:00)×1，新申请[10:00,12:00)×1可行，任一时刻总量仅2。
3. 场地可用而设备缺1件，联合确认应失败，不能先占场地等待设备。
4. 学生申请人把目标场地替换为仅教师可申请会议室，即便时段空闲也不能绕过资格检查。
5. 预览后另一活动占用目标资源，最终改期成为CONFLICTED；原预约保留，原场地有故障则同时显示风险。
6. 资格被改为仅教师申请后，已生效的学生预约保留；其新改期目标按最新资格检查。
