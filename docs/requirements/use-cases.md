# 用例说明

版本：v1.0（依据开发任务包 v2.0；2026-09-26）

所有场景描述的是演示系统规则，并非已经核实的学校制度。API 名称及字段以 `agents/common/02-数据与接口契约.md` 为准。

## 参与者

- 学生（STUDENT）
- 活动组织者（ORGANIZER）
- 教师（TEACHER）
- 资源管理员（RESOURCE_ADMIN）
- 系统管理员（SYS_ADMIN）
- 系统时钟、数据库及统一命令/预约/变更/事件端口（外部协作者）

## UC-ACT-01 创建与维护草稿

**主参与者：** 活动组织者。**前置条件：** 已登录且具 ORGANIZER 角色。

1. 组织者填写活动信息、人数、报名容量、工作人员及计划。
2. 系统验证字段、活动时长、人数关系、工作人员启用状态和组织归属、资源类型及数量。
3. 系统创建活动 DRAFT 和版本 1，初始化独立 lockVersion。
4. 组织者可在 DRAFT 状态编辑；每次成功编辑都插入新不可变版本并递增 lockVersion。

**失败/替代：** 字段无效返回 400；不是所有者返回 403；活动非 DRAFT 或 expectedLockVersion 过期返回 409；失败不产生版本。创建/编辑阶段不预约资源。**验收：** D-AT-03、20。

## UC-ACT-02 提交并审批

**主参与者：** 组织者、教师。**前置条件：** 活动处于 DRAFT，操作者为所有者。

1. 组织者提交当前版本，系统锁定活动并核对 lockVersion。
2. 系统将状态设为 PENDING_TEACHER，记录对应版本及事件，不创建预约。
3. 本组织教师查看审批队列并对该版本批准或驳回，填写意见。
4. 批准后活动进入 APPROVED_UNRESERVED；驳回后回到 DRAFT，保留审批记录。

**失败/替代：** 跨组织教师、非教师或所有者本人审批返回 403；状态或版本已变化返回 409；审批不匹配当前待审版本不得生效。**验收：** D-AT-02、03、20。

## UC-ACT-03 撤回待审或已批准活动

**主参与者：** 活动所有者。**前置条件：** 状态为 PENDING_TEACHER 或 APPROVED_UNRESERVED。

1. 所有者提交撤回理由和 expectedLockVersion。
2. 系统锁活动、校验状态和版本，将当前内容复制为新版本并进入 DRAFT。
3. 旧版本及其审批历史保留，但不能授权新版本进入资源预约。

**失败/替代：** 非所有者返回 403；其他状态或旧 lockVersion 返回 409。**验收：** D-AT-03、20。

## UC-ACT-04 首次联合资源确认

**主参与者：** 资源管理员。**前置条件：** 活动为 APPROVED_UNRESERVED，且管理员已登录。

1. 管理员提交 expectedLockVersion。
2. 系统通过统一命令执行器开始事务，先锁活动并检查状态和版本。
3. SchedulingPort 按资源 UUID 顺序锁定所需资源并检查场地、开放时间、故障及器材容量。
4. 全部可行时，系统更新状态为 SCHEDULED、设置 effectiveVersionNo、写入整组预约并追加事件，事务提交。
5. 管理员收到活动结果。

**失败/替代：** 检查冲突返回 409 RESOURCE_CONFLICT，列出可见冲突；活动仍为 APPROVED_UNRESERVED，不写任何部分预约。并发竞争时至多一个冲突资源请求成功，失败请求不占用资源。**验收：** D-AT-03、07。

## UC-ACT-05 开放报名

**主参与者：** 活动所有者。**前置条件：** 活动为 SCHEDULED、尚未开始且 resourceRisk 为 NORMAL。

1. 所有者提交 expectedLockVersion。
2. 系统锁活动并检查身份、状态、开始时间和最新风险。
3. 系统将状态改为 OPEN、递增 lockVersion 并记录事件。

**失败/替代：** 非所有者 403；活动未完成资源确认、已开始、存在风险或版本过期时返回 409，不开放。**验收：** D-AT-03、18、20。

## UC-REG-01 报名或退出

**主参与者：** 学生。**前置条件：** 已登录且具 STUDENT 角色。

1. 学生选择 OPEN 且未开始的活动，提交 JOIN 或 WITHDRAW 和 expectedVersionNo。
2. 系统锁活动，验证状态、版本、待处理改期及学生本人身份。
3. JOIN 时计数 ACTIVE 报名；有余量则创建/恢复唯一报名记录为 ACTIVE。重复 JOIN 返回原记录。
4. WITHDRAW 时将本人记录置为 WITHDRAWN。重复退出返回原记录；退出后重新加入时重新核验容量。
5. 实际状态变化时递增活动 lockVersion；无变化的幂等返回不重复递增。

**失败/替代：** 非 OPEN、已开始、版本旧或存在待处理改期返回相应 409；容量耗尽返回 CAPACITY_FULL；未有报名历史的退出返回 INVALID_STATE。并发下 ACTIVE 总数不超过容量。**验收：** D-AT-15、16、20。

## UC-ACT-06 取消活动并释放资源

**主参与者：** 活动所有者。**前置条件：** 活动尚未开始且未取消。

1. 所有者提交取消理由和 expectedLockVersion。
2. 系统锁活动，验证所有权后保存当前组织者、工作人员和有效报名收件人快照。
3. 系统通过 ChangePort 取消待处理改期，通过 SchedulingPort 释放预约，取消有效报名，将活动设为 CANCELLED 并追加事件；操作处于同一事务。
4. 同一所有者再次取消已取消活动时，返回当前结果且不重复释放或重复执行副作用。

**失败/替代：** 非所有者即使活动已终态也返回 403；旧版本冲突返回 409。取消与改期资源确认竞争时，共享活动锁，不能使已取消活动复活。**验收：** D-AT-17。

## UC-ACT-07 查看活动与名单

**主参与者：** 学生、组织者、教师、资源管理员。系统按角色和归属过滤活动列表、审批队列、详情及名单。公开列表只显示 OPEN 活动；mine 只返回当前用户所有活动。活动详情计算报名数、风险、活动当前版本、有效版本和待处理改期；普通学生只看到自己的报名状态。越权访问返回 403，不存在对象返回 404。**验收：** D-AT-02、21。

## 改期交互用例边界

活动模块提供 ActivityPort 快照、锁、活动计划激活及 lockVersion 递增能力；预览/改期状态和变更记录由 scheduling/change 所有者实现。目标计划不能由活动服务直接改活动版本或预约。完整改期由基线第 6 节及 D-AT-09—14 定义；取消时通过 ChangePort 使待处理改期进入 CANCELLED_BY_ACTIVITY。**验收：** D-AT-10—15、17、20。
