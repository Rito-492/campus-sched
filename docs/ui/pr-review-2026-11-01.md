## 必须改（阻塞本次建议放行）

### 1. [P2] 刷新资源后，申请资格表单仍保留旧开关值

位置：`web/src/components/ResourceManagePanel.vue:85`（监听 `selectedId/revision`）、`web/src/pages/ResourceManagePage.vue:54`（更新资源数组）。

触发：资源管理员选中一个教师/学生均可申请的资源；另一个操作将两项资格关闭；管理员在原页点击“刷新资源与权限”。真实 GET 已返回两个 `false`，页面两个开关仍为勾选。原因是同一资源 ID 不变，手动 `load()` 不递增 `revision`，更新资源数组不能触发表单同步。若继续保存，`saveEligibility()` 仍发送旧的两个 `true`，存在无意重新开放资格的风险。

本次已用组件测试和真实服务浏览器分别复现：服务器 `false/false`，界面 `true/true`。真实测试只验证显示，没有继续保存旧值。依据：UI-04 的 API-40 申请资格管理、common/02 API-07/40；刷新后的编辑值应能反映服务端现状，或明确标记保留的未保存改动，不能无提示展示陈旧值。

建议：将成功刷新后当前选中资源的资格变化纳入表单同步；有未保存输入时明确处理冲突。补充“选中同一资源→外部变更→手动刷新→界面与服务一致→保存不回滚资格”的回归。

证据：`diagnostics.json/log`、`real-eligibility-results.json/log`、`eligibility-observed.json`；截图 `eligibility-refresh-stale.png`。

### 2. [P2] 用裁剪后的人员数组判断权限，导致普通工作人员无法打开改期历史

位置：`web/src/domain/change.ts:98`（`recordAccess().changes`）、`web/src/components/ActivityRecords.vue:102`（隐藏页签）。

触发：普通工作人员参与的改期已生效或结束，打开活动详情。API-14 对非所有者/审核人裁剪 `input.staffUserIds=[]`，但该工作人员对 API-28 仍有合法读取权。前端用这个空数组判断“不是工作人员”，隐藏改期记录页签；结束后 `activeChangeId=null`，当前改期快捷入口也消失，通知又只跳到活动页，用户无法正常进入已有历史。

本次真实账号 `staff_a`：活动 GET 200、人员数组为空、`activeChangeId=null`；同一会话访问 `/activities/{id}/changes` 返回200及1条已生效记录，但页面“改期记录”页签数量为0。不是后端拒绝访问，也不是无历史数据。

依据：common/02 API-28/29 明确允许该活动工作人员读取，HTTP 裁剪规则不能当作否定本人关系的证明；UI-05 要交付历史入口。建议依据历史接口的授权结果处理可访问性，或经 PM 协调显式能力字段；不要通过扩大工作人员隐私数据披露来绕过问题。补普通工作人员在待处理/已生效/已拒绝或撤回后的入口回归。

证据：`real-history-results.json/log`、`staff-history-observed.json`；截图 `staff-history-missing.png`。
